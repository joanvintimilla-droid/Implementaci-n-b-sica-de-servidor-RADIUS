04 / VALIDACIÓN

Pruebas y troubleshooting

Comprobaciones para verificar que el servidor responde y autentica correctamente.

Pruebas de aceptación

TC-01freeradius -CXConfiguración válida: Configuration appears to be OK.
TC-02systemctl status freeradiusServicio activo: active (running).
TC-03ss -lunpPuertos UDP 1812 y 1813 en escucha.
TC-04radtest juan juan localhost 0 <secreto>Credenciales correctas: Access-Accept.
TC-05Probar una clave incorrecta.Resultado esperado: Access-Reject.
AccountingVerificar el puerto 1813.Respuesta esperada: Accounting-Response.
Cargaradclient -c 100 -p 10100 peticiones, 10 en paralelo.
TC-06freeradius -XObservar el rechazo de sesión PEAP en la salida de depuración.
TC-07tcpdump -ni eth0 host 192.168.0.1Comprobar tráfico real del router.
TC-08timedatectlVerificar System clock synchronized: yes.
TC-10ss -lunpConfirmar que 1812/1813 continúan en escucha.

Verificaciones adicionales de referencia

Para HTTP/FTP/NTP en producción, el README propone estas comprobaciones:

ntpq -p
curl -I http://servidor
curl -T archivo ftp://servidor/

Para FTP activo también se menciona --ftp-port -.

Errores frecuentes y soluciones

ProblemaCausa posibleSolución documentada
El router no llega al RADIUS (unknown client).Firewall, IP o secreto distintos.firewall-cmd --add-service=radius; igualar IP y secreto; revisar con tcpdump -ni eth0 udp port 1812.
SELinux bloquea lectura o escritura.Etiquetas incorrectas.ausearch -m avc y restorecon -Rv /etc/raddb. No usar setenforce 0.
Error de certificado aunque la clave sea correcta.Reloj desfasado.Revisar timedatectl, activar chronyd con systemctl enable --now chronyd y regenerar certificados con make destroycerts && make.
Consejo

Ejecuta las pruebas en orden: primero valida la configuración, después el servicio y los puertos, y finalmente la autenticación desde el cliente.
